# 缓存管理协议

## 支持的语义

管理的是**完成请求后实际计算过、可复用的前缀**，不是运行中请求的 sampler／RNG／队列状态热迁移。

开启 `--enable-prefix-caching --enable-cache-management` 后：

- `keep_cache_in_gpu=true, free_cache=false` 持有真实 GPU 块引用。
- `keep_cache_in_gpu=false, free_cache=false` 将实际 KV／GDN／MTP 页复制到 CPU，再释放 GPU 引用。
- 下次匹配调用可分配新 GPU 页并实际 H2D，登记目的引擎的原生哈希。
- `free_cache=true` 释放本会话显式所有者；不重复释放其他合法共享引用。

必须检查响应中的实际保存状态；生成成功不等于驻留成功。预算不足、无完整 hybrid 边界或不支持的布局会明确报告。

## 页布局

按分配器页而非 attention kernel tile 搬运。hybrid 的连续原始页覆盖 full attention、GDN 和 MTP；普通 K/V 分平面布局通过 `PageStorage` 沿真实 block 轴收集与写回，使用 allocator/kernel block factor，不能假定物理页是连续切片。

恢复先校验 CPU 字节，再复制到预留 GPU 页并回读 SHA256。所有 rank 成功后才发布哈希；失败回滚新分配块。MTP 保留必要的、已经实际计算且具有哈希的保护页，不发布未提交 speculative 尾部。

## 容量与预测式驻留

`--retained-gpu-fraction` 限制显式 GPU 驻留；手动硬 pin 不因普通压力静默换走。CPU预算按 worker计，总上限约为 `cpu_cache_bytes × TP`。实际字节在 `/cache_state` 报告。

可选 `--cache-policy-profile` 与请求 `cache_policy=predictive`，比较预期工具等待与换出／恢复成本，短等待保留 GPU、到期在安全边界真实换出。工具历史按 agent/tool学习；无历史和提示时优先 CPU。

`/cache/swap_profile` 记录实际事务成本，包含 RPC、哈希和校验；不等于纯 tensor 拷贝。单一大小只形成该大小的观测成本，多个大小才拟合线性项，超出范围使用声明先验或回退 CPU。

## 同机跨实例迁移

1. 源只导出实际持有的缓存；必要时先 D2H。
2. 同机私有共享目录传真实 CPU tensor artifact，附布局与字节校验。
3. 目标检查模型、版本、dtype、K、TP与全部 group 布局。
4. 目标分配物理页、H2D并回读校验，以自身原生 hasher登记。
5. 目标成功后才确认释放源；失败不销毁仍有效的源缓存。

当前只支持相同模型／K／TP，不能跨主机或跨 K。无法迁移时可以使用完整 prompt安全重算，但不能将重算报告为迁移成功。

## 路由与 API

默认严格区间；可选 `coreflow` 路由保留缓存优先次序，但外区间请求必须实际原生命中且实例显式允许 affinity。完成后越界的前缀可迁移到兼容分区；最终释放时清理同会话其他分区残留。

接口：`/cache_state`、`/cache/lookup`、`/cache/offload`、`/cache/restore`、`/cache/release`、`/cache/export`、`/migrate_cache`。仅 loopback、可信同机环境，不能作为无鉴权公网传输服务。
